Why is Flat JSON 188x to 448x Slower on Disk?

The fundamental bottleneck is full-file deserialization and serialization on every single mutation.

❌ Flat JSON File Persistence

  • Reads the entire 2MB JSON file from disk into RAM.
  • Deserializes all 10,000 objects into the .NET CLR heap.
  • Performs an O(N) linear iteration to locate the targeted document.
  • Re-serializes all 10,000 objects back into a massive 2MB JSON string.
  • Rewrites the entire file to disk for every single document mutation.
  • 10 mutations = 11.5 seconds of disk blocking!
  • Zero concurrency; high risk of JSON file corruption on interruption.

✅ PSLocalBase (SQLite NoSQL Engine)

  • Locates the target row in O(log N) via SQLite's B-Tree index.
  • Performs an in-place page modification in Write-Ahead Logging (WAL) mode.
  • Modifies only the affected ~4KB page without touching the rest of the database.
  • 10 mutations = 61 milliseconds (188.5x faster!).
  • In-Memory mode syncs cleanly to disk via atomic C-level VACUUM INTO in 54ms.
  • Full ACID transactions with instant rollback and non-blocking concurrency.
